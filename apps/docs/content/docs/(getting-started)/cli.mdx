Use the `openagentui` CLI to set up new projects and add components to existing ones.

## init

Use the `init` command to add openagentui to an existing project.

```bash
npx openagentui@latest init
```

This will:
- Exit with a notice if the project already has a `components.json`
- Run `create` instead if the directory has no `package.json`
- Run `shadcn init` to configure the project
- Use `shadcn add` to install the openagentui quick-start component
- Add the default openagentui components (thread, composer, etc.) to your project

When `init` sets up an existing project in a non-interactive shell such as CI, pass `--yes`. Without it, `init` exits with an error because it cannot prompt.

**When to use:**
- Adding openagentui to an **existing** Next.js project
- First-time setup in a project with `package.json`

**Options**

```bash
Usage: openagentui init [options] [project-directory]

initialize openagentui in an existing project

Arguments:
  project-directory  directory for the new project

Options:
  -y, --yes          skip confirmation prompt. (default: false)
  -o, --overwrite    overwrite existing files. (default: false)
  -c, --cwd <cwd>    the working directory. defaults to the current directory.
  --use-npm          explicitly use npm
  --use-pnpm         explicitly use pnpm
  --use-yarn         explicitly use yarn
  --use-bun          explicitly use bun
  --skip-install     skip installing packages
  -h, --help         display help for command
```

## create

Use the `create` command to scaffold a new Next.js project with openagentui pre-configured.

```bash
npx openagentui@latest create [project-directory]
```

This command scaffolds a project from openagentui starter templates or examples.

**Available Templates**

| `cloud-clerk` | Cloud-backed starter with Clerk auth | `npx openagentui create -t cloud-clerk` |

## cloud

Use `cloud setup` to create a multiplayer chat backed by a hosted
[harness](/docs/cloud/harnesses):

```bash
npx openagentui@latest cloud setup multiplayer-chat
```

The command signs you in with browser device OAuth, selects or creates an
organization and project, provisions the harness, and installs a Next.js app.
Add your `OPENAI_API_KEY` to its `.env.local`, then run the app's `dev` script.
Open `http://localhost:3000/#main` in two browsers to join the same conversation.
Both clients receive the shared messages and streaming replies. **Share this
chat** copies the current thread's URL.

For a script or coding agent, select cloud resources with flags:

```bash
npx openagentui@latest cloud setup multiplayer-chat --org team --new-project hackathon-chat --backend-url http://localhost:3000/api/chat --yes
```

| Option | Effect |
| --- | --- |
| `--org <id-or-slug>` | Select an existing organization. |
| `--new-org <slug>` | Create an organization. |
| `--project <id-or-slug>` | Select an existing project. |
| `--new-project <slug>` | Create a project. |
| `--name <name>` | Set the display name of a new organization or project. |
| `--harness-name <name>` | Name the shared chat harness. |
| `--backend-url <url>` | Set the absolute chat endpoint; defaults to `http://localhost:3000/api/chat`. |
| `--access-code <code>` | Redeem a hackathon harness access code; also reads `OPENAGENTUI_ACCESS_CODE`. |
| `--api-url <url>` | Select the cloud management server; also reads `OPENAGENTUI_CLOUD_URL`. |
| `--no-open` | Print the device sign-in URL without opening a browser. |
| `--setup-url <url>` | Show device approval in the active setup wizard while the CLI completes sign-in. |
| `--yes` | Skip prompts; choose resources with flags. |
| `--skip-install` | Leave dependency installation to you. |
| `--use-npm`, `--use-pnpm`, `--use-yarn`, `--use-bun` | Choose a package manager. |

The server's project API key is written to `.env.local` with owner-only
permissions and a Git ignore entry. Public environment values identify the
cloud API, harness origin, and workspace. `.openagentui/cloud.json` records
the selected cloud resources. Existing environment values are preserved, and
conflicting settings stop setup.

The starter's `/api/credential` route issues short-lived credentials for the
shared `hackathon` user. The browser uses `HarnessCloudThreadList` to connect
to the hosted conversation, and the AI SDK chat route holds the model API key.
Add application authentication to `/api/credential` for private access or
individual users. Local development uses the runtime's browser tunnel; a
deployed app supplies its public HTTPS chat endpoint to `--backend-url` during
initial setup. To deploy a chat already configured locally, update the harness
backend allowlist in the Cloud dashboard and `backendUrl` in
`.openagentui/cloud.json`, then rerun with the same HTTPS `--backend-url`.
Existing conversations keep their original backend, so open the deployed app
with a fresh thread fragment such as `#deployed-chat`, then use **Share this
chat**. Setup rejects a changed backend URL instead of silently ignoring it.

Run `npx openagentui@latest cloud setup .` inside a generated cloud-harness app to resume
setup. `npx openagentui@latest cloud login` signs in separately; `npx openagentui@latest cloud login --no-open`
prints the sign-in URL. `npx openagentui@latest cloud logout` revokes and removes the
saved CLI credentials.

In an active setup wizard, an agent can pass its setup-agent URL to `cloud login`
or `cloud setup` with `--setup-url <url>`. The wizard displays the public code,
then opens Accounts for explicit approval and returns to the same setup. It
waits for the CLI to poll Accounts and save owner-only credentials locally;
returning alone never completes login. Tokens never pass through the wizard or
its secret inputs. Cancelling the question or setup ends a pending login.

Before the npm patch is released, wizard sign-in is available in the
[verified CLI prerelease](/downloads/openagentui-wizard-login-ea9aae48e.tgz).
Use the active setup-agent connection URL supplied by your agent:

```bash
npx --yes --package=https://openagentui.dev/downloads/openagentui-wizard-login-ea9aae48e.tgz openagentui cloud login --setup-url "<active-setup-agent-url>"
```

This prerelease is separate from the existing hackathon setup download.

## add

Use the `add` command to add individual components to your project.

```bash
npx openagentui@latest add [component]
```

The `add` command runs `shadcn add` against the openagentui registry. It copies each component's source into your project and installs the dependencies the component needs.

**Popular Components**

```bash
# Add the basic thread component
npx openagentui add thread

# Add thread list for multi-conversation support
npx openagentui add thread-list

# Add assistant modal
npx openagentui add assistant-modal

# Add multiple components at once
npx openagentui add thread thread-list assistant-sidebar
```

**Options**

```bash
Usage: openagentui add [options] <components...>

add a component to your project

Arguments:
  components             the components to add

Options:
  -y, --yes              skip confirmation prompt. (default: true)
  -o, --overwrite        overwrite existing files. (default: false)
  -c, --cwd <cwd>        the working directory. defaults to the current directory.
  -p, --path <path>      the path to add the component to.
  --use-npm              explicitly use npm
  --use-pnpm             explicitly use pnpm
  --use-yarn             explicitly use yarn
  --use-bun              explicitly use bun
  -h, --help             display help for command
```

## update

Use the `update` command to update all `@openagentui/*`, `openagentui-stream`, and `openagentui-cloud` packages to their latest versions.

```bash
npx openagentui@latest update
```

This command:
- Scans your `package.json` for openagentui packages
- Updates them to the latest versions using your package manager
- Preserves other dependencies

**Examples**

```bash
# Update all openagentui packages
npx openagentui update

# Dry run to see what would be updated
npx openagentui update --dry
```

**Options**

```bash
Usage: openagentui update [options]

Update all '@openagentui/*' and 'assistant-*' packages in package.json to latest versions using your package manager.

Options:
  --dry            Print the package manager command instead of running it.
  -c, --cwd <cwd>  the working directory. defaults to the current directory.
  -h, --help       display help for command
```

The command matches `@openagentui/*`, `openagentui-stream`, and `openagentui-cloud` in `dependencies` and `devDependencies`.

## upgrade

Use the `upgrade` command to migrate your codebase after breaking changes.

```bash
npx openagentui@latest upgrade
```

This command:
- Applies the current bundled codemods sequentially to update import paths and API usage
- Shows a progress bar with file count
- Reports any transformation errors
- Detects new package dependencies and prompts to install them

The latest upgrade excludes the historical v0.8 UI package split because its
`@openagentui/react-ui` destination is incompatible with current runtime versions.
Do not run `codemod v0-8/ui-package-split` as part of a v0.15 upgrade.

**Example output:**

```bash
Starting upgrade...
Analyzing codebase...
Found 24 files to process.
Progress |████████████████████| 100% | ETA: 0s || Running v0-11/content-part-to-message-part...
Checking for package dependencies...
✓ Upgrade complete!
```

**Options**

```bash
Usage: openagentui upgrade [options]

Upgrade ai package dependencies and apply codemods

Options:
  -d, --dry              Dry run (no changes are made to files)
  -p, --print            Print transformed files to stdout
  --verbose              Show more information about the transform process
  -j, --jscodeshift <options>  Pass options directly to jscodeshift
  -h, --help             display help for command
```

## codemod

Use the `codemod` command to run a specific codemod transformation.

```bash
npx openagentui@latest codemod <codemod> <source>
```

Use it to run one migration instead of the full `upgrade` bundle.

**Examples**

```bash
# Run specific codemod on a directory
npx openagentui codemod v0-11/content-part-to-message-part ./src

# Run with dry run to preview changes
npx openagentui codemod v0-11/content-part-to-message-part ./src --dry

# Print transformed output
npx openagentui codemod v0-11/content-part-to-message-part ./src --print
```

**Options**

```bash
Usage: openagentui codemod [options] <codemod> <source>

CLI tool for running codemods

Arguments:
  codemod                Codemod to run (e.g., rewrite-framework-imports)
  source                 Path to source files or directory to transform

Options:
  -d, --dry              Dry run (no changes are made to files)
  -p, --print            Print transformed files to stdout
  --verbose              Show more information about the transform process
  -j, --jscodeshift <options>  Pass options directly to jscodeshift
  -h, --help             display help for command
```

## agent

Use the `agent` command to open Claude Code with the openagentui skills loaded and a prompt already sent.

```bash
npx openagentui@latest agent "add a chat sidebar to this app"
```

The command fetches the [openagentui skills](/docs/llm#skills) plugin pinned to this CLI release into `~/.cache/openagentui/skills/<commit>` (under `$XDG_CACHE_HOME` when set), then runs `claude` with `--plugin-dir` for that session only. Nothing is written into your project; run `npx skills add openagentui/skills` to install the skills permanently. The `claude` CLI must be on your `PATH`, and a `GITHUB_TOKEN` avoids GitHub's unauthenticated rate limit on the first fetch.

**Options**

```bash
Usage: openagentui agent [options] <prompt...>

launch Claude Code with openagentui skills

Arguments:
  prompt      prompt for the agent

Options:
  --dry       print the command instead of running it
  -h, --help  display help for command
```

## doctor

Use the `doctor` command to find duplicate or outdated openagentui packages in `node_modules`, including transitive ones.

```bash
npx openagentui@latest doctor
```

This command:
- Reports packages installed in more than one version and exits with code 1 when it finds any
- Checks the npm registry and reports packages that are behind the latest version
- Recommends `npx openagentui update` to fix either problem

**Options**

```bash
Usage: openagentui doctor [options]

Diagnose mismatched or outdated openagentui packages (including transitive ones).

Options:
  -c, --cwd <cwd>  the working directory. defaults to the current directory.
  --no-network     Skip the npm registry check for latest versions.
  -h, --help       display help for command
```

## Common Workflows

### Starting a new project

```bash
# Create a new project with the default template
npx openagentui@latest create my-chatbot

# Navigate into the directory
cd my-chatbot

# Start development
npm run dev
```

### Adding to existing project

```bash
# Initialize openagentui
npx openagentui@latest init

# Add additional components
npx openagentui@latest add thread-list assistant-modal

# Start development
npm run dev
```

### Keeping up to date

```bash
# Check for updates (dry run)
npx openagentui@latest update --dry

# Update all packages
npx openagentui@latest update

# Run upgrade codemods if needed
npx openagentui@latest upgrade
```

### Migrating versions

```bash
# Run automated migration
npx openagentui@latest upgrade

# Or run specific codemod
npx openagentui@latest codemod v0-11/content-part-to-message-part ./src

# Update packages after migration
npx openagentui@latest update
```

## Component Registry

The CLI pulls components from the public registry at [r.openagentui.dev](https://r.openagentui.dev).

Configure the style-aware URL in `components.json` so `@openagentui/*` installs match your shadcn style:

```json title="components.json"
{
  "registries": {
    "@openagentui": "https://r.openagentui.dev/styles/{style}/{name}.json"
  }
}
```

The `{style}` placeholder is filled from your `components.json` `style` field. Styles whose name starts with `base-` resolve to Base UI flavored components; every other style resolves to Radix. Existing Radix projects can keep `https://r.openagentui.dev/{name}.json` as a fallback.

Each registry item lists its TypeScript source files and the dependencies to install. Components are added to your project's source code, so you can edit them.

## Troubleshooting

### Command not found

If you get a "command not found" error, make sure you're using `npx`:

```bash
npx openagentui@latest init
```

### Permission errors

On Linux/macOS, if you encounter permission errors:

```bash
sudo npx openagentui@latest init
```

Or fix npm permissions: https://docs.npmjs.com/resolving-eacces-permissions-errors-when-installing-packages-globally

### Diagnosing issues

When filing a bug report, run `npx openagentui info` to collect environment details:

```bash
npx openagentui info
```

Paste the output into the "Environment info" field of the [bug report template](https://github.com/RealDealCPA-VR/OpenAgentUI/issues/new?template=bug_report.yml).

### Conflicting dependencies

If you see dependency conflicts:

```bash
# Try with --force flag
npm install --force

# Or use legacy peer deps
npm install --legacy-peer-deps
```

### Component already exists

Use the `--overwrite` flag to replace existing components:

```bash
npx openagentui@latest add thread --overwrite
```

## Configuration

The CLI respects your project's configuration:

- **Package Manager**: Automatically detects npm, pnpm, yarn, or bun
- **TypeScript**: Works with your `tsconfig.json` paths
- **Tailwind**: Uses your `tailwind.config.js` settings
- **Import Aliases**: Respects `components.json` or `openagentui.json` configuration
